# Project Nebula · 四阶段重构复盘与阶段 5 验收

**审计日期：** 2026-11-11  
**审计分支：** `feat/capability-map-audit-v1`  
**审计依据：** 当前首页结构、四轮重构代码、各阶段 PR 说明、当前景观白绿设计规范，以及本分支的静态检查结果。

## 一、结论先行

- 当前网站的四个主内容区为「个人奇点、经历与成长、作品与实践、思考与方法」，另有联系区；侧栏目录、内容卡片、抽屉和第三级查看器构成主要浏览路径。
- 前四阶段已形成完整代码链：响应式与个人区调整、全站双语、景观白绿视觉系统、多媒体与第三级阅读器。
- 本次阶段 5 在「作品与实践」中增加四域能力图谱，并对颜色、字体、按钮、响应式和交互规范做了校准。
- **视觉系统整体达到当前设计规范的主要层级。** 色彩语义清晰、正文对比度充足、字体层级可读、主次按钮尺寸统一；小字号集中用于标签和 metadata。
- **代码静态检查通过，但真实浏览器验收尚未完成。** 不能仅凭静态 CSS 断言手机端卡片、抽屉堆叠和媒体播放已经达到最终体验。
- 发布状态需要区分：阶段 1 PR #4 已合并；阶段 2–4 的 PR #5–#7 仍在依赖链上开放；阶段 5 PR #8 为 Draft，尚未进入 main。

## 二、当前页面结构与布局判断

| 页面区域 | 当前实现 | 自检判断 |
| --- | --- | --- |
| 全局导航 | 桌面固定侧栏；平板与手机切换为顶部导航和折叠菜单 | 信息入口清楚，导航模式随屏宽切换合理 |
| 个人奇点 | 双栏卡片，左侧身份与能力，右侧观点、数字分身状态与能力卡 | 结构平衡；窄屏改为单列，需实机检查文字长度 |
| 经历与成长 | 时间线/经历条目，含 Project Nebula 实践经历 | 时间顺序和项目入口明确 |
| 作品与实践 | 工作项目、个人项目、能力图谱、相关作品材料 | 内容分组明确；能力图谱先讲能力，再提供项目证据，避免重复项目正文 |
| 思考与方法 | 文章列表与详情抽屉 | 适合快速浏览与深度阅读 |
| 联系区 | 页面底部统一联系入口 | 浏览路径完整 |

**布局参数**

- 桌面侧栏：264px。
- 主内容区块：最大宽度 1200px。
- 详情抽屉：最大宽度 760px。
- 第三级查看器：最大宽度 1120px。
- 响应式断点：1100 / 960 / 760 / 560 / 380px。
- 960px 以下侧栏切换为顶部导航；760px 以下个人区和能力卡片切为单列；560px 与 380px 继续压缩卡片与边距。

**判断：** 当前页面结构从个人介绍到经历、作品、文章，符合个人网站的浏览顺序。桌面侧栏提供稳定定位，内容区限制阅读宽度，详情通过抽屉和模态查看器逐层展开。整体没有明显的信息架构冲突。下一步应重点检查 390px 手机端的标题换行、卡片高度、抽屉按钮可达性，以及 820px 平板导航展开后的遮挡问题。

## 三、视觉规范自检

### 1. 色彩

当前主题变量：

| 角色 | 色值 | 白底对比度 | 使用判断 |
| --- | --- | ---: | --- |
| 正文墨绿灰 | #26342D | 13.03:1 | 正文和主要标题，清晰 |
| 辅助苔灰 | #66746C | 4.91:1 | 辅助文字，满足常见 AA 文本对比要求 |
| 主强调森林绿 | #285C43 | 7.77:1 | 主按钮、当前导航和关键链接 |
| 辅助植被绿 | #4F755D | 5.20:1 | 次级强调和辅助标签 |
| 装饰雾绿 | #B9CCBE | 1.69:1 | 仅用于装饰和边界，不用于正文 |
| 边界雾绿 | #DCE6DE | 1.28:1 | 仅用于卡片边框和分隔线 |
| 弱化底色 | #F5F8F6 / #EDF3EF | — | 次级表面和主色弱化背景 |

**判断：** 色彩体系克制，主色与正文色的对比度充足；低对比度雾绿被限制在边界和装饰用途，方向合理。后续新增组件应继续使用语义变量，避免直接写入新的绿色色值。

### 2. 字体与信息层级

当前字体栈为 Noto Sans SC、思源黑体、PingFang SC、Microsoft YaHei 的系统回退组合；代码与编号使用等宽字体栈。没有随站点加载外部字体文件，因此不同系统可能显示不同的本机字体。

| 层级 | 当前字号 | 页面用途 |
| --- | ---: | --- |
| Display | 40–44px | 首屏主标题与最重要的视觉句 |
| Section title | 28–34px | 主内容区标题 |
| Group title | 21px | 经历分组、项目分组与能力区标题 |
| Card title | 16px | 项目卡片与内容卡片标题 |
| Detail H2 / H3 | 19px / 15px | 抽屉正文内部标题 |
| Body | 16px / 1.75 | 主要正文 |
| Section lead | 14px | 区块引导文字 |
| Card summary | 13px | 项目与材料摘要 |
| Caption | 12px | 简短辅助信息 |
| Eyebrow / Tag | 约 11px | 区块标记、标签 |
| Metadata | 10px | 日期、编号、状态等短信息 |

**判断：** 正文 16px、摘要 13px、辅助文字 14px 的分层基本合理。10px 只适合日期和编号，不应承载说明句；标签和项目技术栈可用 11px，但不应把长内容压缩成小字。本次已把设计规范示例调整为实际页面正在使用的字号，而不是只展示未被组件采用的抽象层级。

### 3. 按钮与交互组件

| 组件 | 当前尺寸 | 自检判断 |
| --- | ---: | --- |
| 主按钮 / 次按钮 | 最小高度 40px | 主要操作层级清晰 |
| 图标按钮 | 40×40px | 点击区域明确 |
| 语言切换 | 最小高度 36px | 紧凑但可用，手机端需检查实际触控 |
| 媒体 Tab | 最小高度 36px | 视觉一致，已增加方向键与 Home/End 支持 |
| 侧栏辅助入口 | 最小高度 36px | 作为次级入口合理 |
| 能力证据入口 | 最小高度 44px | 触控区域更充足 |
| 文本链接 | 轻量操作 | 不应替代关键 CTA |

当前组件状态包含 hover、focus-visible 和 disabled；媒体 Tab 有选中与非选中样式。抽屉/查看器使用堆叠式 dialog，保留关闭后返回原操作位置的交互逻辑。

**判断：** 主次按钮区分明确，控件高度已经有共享 token 管理。后续需要重点确认移动端点击区域、焦点描边在白底上的可见性，以及连续打开抽屉和查看器时焦点恢复是否稳定。
